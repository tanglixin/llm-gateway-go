# 3 分钟演示脚本

面向「给面试官 / 同事 / 客户讲一遍」的场景。每一步都写了**点什么、说什么、看什么**。

前置：`make up && make run`，浏览器打开 <http://127.0.0.1:8080/>。

---

## 0:00–0:20 开场：登录与租户

**做**：用 `tang@acme.dev` / `gateway` 登录。

**说**：
> 这是一个企业级 RAG 网关。所有接口都要 JWT，租户从 token 里取，不是从请求参数取——
> 客户端改不了自己看哪个租户的数据。

**看**：顶栏显示 `唐立新 / acme-rd · admin`。

---

## 0:20–0:50 知识库：一份文档 2 秒入库

**做**：知识库页 → 点「＋ 上传文档」→ 随便选一个 `.md` 文件。

**看**：新行从 `解析中` → `切分中` → `向量化` → `入库中` → `就绪`，行数 +1。

**说**：
> 原件进 MinIO，任务进 Redis 队列，后台 worker 跑五个阶段：解析（PDF/DOCX/MD/TXT）、
> 切分、nomic-embed-text 向量化、写 pgvector、就绪。
> 状态全在数据库里，worker 崩了重启不会丢进度。

---

## 0:50–1:20 检索：三种策略的真对比

**做**：检索调试台 → 在查询框输入「一线城市住宿上限是多少」→ 依次切 BM25 / 向量 / 混合。

**看**：同一句话，三种模式返回的片段和分数不同（`bm25 19.9` / `cosine 0.78` / `rrf 0.03`）。

**说**：
> BM25 用字符 bigram 处理中文，向量走 pgvector 余弦，混合是加权分数融合。
> 下面这张对比表不是写死的——是拿 7 条 Golden Set 现场跑出来的
> Recall@5 / MRR / NDCG@5。

**加分**：滑到对比表，指出 `BM25 0.86 / 向量 0.69 / 混合 0.79`，说：
> 混合没有赢，因为这批查询几乎都是原文词。我把它记成了待优化项，没去调参凑好看。

---

## 1:20–2:00 问答：流式 + 引用

**做**：智能问答 → 输入「一线城市住宿上限是多少」→ 回车。

**看**：文字逐字出现（首字约 0.2 秒），下方出现 3 张引用卡，右侧检查器显示真实 token 数与延迟。

**说**：
> 服务端是 SSE，每帧一个 chunk，最后一帧带 usage 和 ttft。
> 引用卡来自检索结果，点开能看到原文片段。
> 检查器里的 Prompt/Completion tokens 是模型真实返回的，不是估的。

**加分**：刷新页面，消息还在 → 「会话和消息都落 PostgreSQL」。

---

## 2:00–2:40 Agent：真的会调工具

**做**：Agent 工作台 → 点「运行 Agent」（约 30 秒）。

**看**：轨迹依次出现 `Action kb_search` → `Observation` → `Thought` → `Final`，右上角出现「数字均可溯源」。

**说**：
> 这是真实的 ReAct 循环，不是回放。模型先检索知识库，工具真的去查 pgvector。
> 轨迹里有一行「规则兜底选择」——因为 0.5B 模型选工具不可靠，我会校验它的选择，
> 明显错配就退回关键词规则，并**如实标注**，不假装是模型决定的。
> 最后这个「数字均可溯源」是校验：终答里的每个数字都要在检索结果里出现过，
> 否则标红——它把 600 说成 200 的时候会被抓住。

**做**：可观测页 → Trace 回放。

**看**：瀑布图三条：

## 常见提问与回答

**Q：为什么不用 LangChain 的 Agent？**
A：用了 langchaingo 的模型调用，但 ReAct 循环是自己写的——需要控制每步的输出长度（小模型自由发挥会跑偏），
也要在轨迹里记录「规则兜底」这类信息，现成框架不好塞。

**Q：为什么没有 Jaeger/Tempo？**
A：Span 写进已有的 PostgreSQL，查起来和业务数据同库。换正式后端只需替换 exporter。

**Q：为什么混合检索没赢？**
A：语料小（13 个分块）且查询都是原文词，BM25 已接近满分。无差别融合会把较弱的向量结果混进来。
真实语料上混合通常更稳，但这句话需要更大的评测集来证明，我没有现成的。

**Q：这个能上生产吗？**
A：核心链路可以，但有三个已知缺口：没有 Postgres RLS（直连库可绕过隔离）、
没有刷新 token / 吊销、ops 的 backup/restore 是模拟实现。都写在 README 的「已知取舍」里。
